# MarkReview AI Workflow

## 使用场景

用户在 VS Code 中通过 MarkReview 给 Markdown 原文插入 CriticMarkup 批注后，可以直接把这份 Markdown 文件交给 Codex 或其他 AI。AI 根据批注直接修改原文件内容，但不要再用 CriticMarkup 表示新增、删除或替换；这些修改差异交给 Git 查看。

这个流程的核心是：Markdown 文件本身仍然是正文和批注的唯一交接物，批注意见作为审阅记录保留在原文中。

## 用户操作流程

1. 在 VS Code 中打开 Markdown 文件。
2. 使用 MarkReview 命令添加批注。
3. 检查文档中的 CriticMarkup 批注是否表达清楚。
4. 使用 `MarkReview: Export AI Prompt` 生成提示词，或复制下方稳定模板。
5. 将提示词交给 Codex；提示词中包含当前 Markdown 原文文件地址。
6. Codex 直接修改原 Markdown 文件，不新增 CriticMarkup 修订标记。
7. 用户通过 Git diff 查看 AI 做了哪些新增、删除和替换。
8. 原批注保留在 Markdown 中，供用户回看审阅依据或后续清理。

## 稳定提示词模板

````text
你是一个谨慎的 Markdown 修改助手。请读取下面的 Markdown 原文文件，根据其中的 CriticMarkup 批注直接修改文件内容。

原文文件地址：
{{Markdown 原文文件的本地路径}}

CriticMarkup 规则：
- {++新增内容++} 表示已有新增建议。
- {--删除内容--} 表示已有删除建议。
- {~~旧内容~>新内容~~} 表示已有替换建议。
- {==被标记内容==}{>>批注意见<<} 表示已有批注。

处理要求：
- 直接修改上述 Markdown 文件，不要另外输出一份带修改标记的版本。
- 修改正文时不要新增 CriticMarkup 标记；新增、删除、替换都直接改正文，差异由 Git 查看。
- 保留原有批注标记，尤其是 {==被标记内容==}{>>批注意见<<}；如果根据批注改写了被标记内容，只更新 {==...==} 内的正文，并保留 {>>...<<} 批注意见。
- 对已有 {++...++}、{--...--}、{~~...~>...~~} 修订建议，如决定接受，请直接改成最终正文并移除这些修订标记。
- 保持标题、列表、表格、引用、代码块、链接和图片等 Markdown 结构。
- 不要改写无关内容，除非为了局部语义连贯需要做很小调整。
- 如果批注意见不明确，采用最保守、最贴近上下文的修改。
````

## Agent 处理规则

| CriticMarkup | Agent 应做的事 | 修改后状态 |
| --- | --- | --- |
| `{++新增内容++}` | 如接受新增建议，直接保留新增内容 | `新增内容` |
| `{--删除内容--}` | 如接受删除建议，直接删除该内容 | 空 |
| `{~~旧内容~>新内容~~}` | 如接受替换建议，直接使用 `~>` 右侧内容 | `新内容` |
| `{==内容==}{>>意见<<}` | 根据意见改写被标记内容，但保留原批注意见 | `{==改写后的内容==}{>>意见<<}` |
| `{==内容==}` | 没有批注意见时保守保留内容和高亮 | `{==内容==}` |
| `{>>意见<<}` | 缺少明确作用对象时保留批注，除非能安全关联上下文 | `{>>意见<<}` |

## 示例

修改前：

```markdown
MarkReview 是一个{++轻量级++} Markdown 审阅插件。

{==它可以做很多文档管理功能==}{>>第一版不要夸大范围，强调小而可用。<<}

用户{--需要维护额外的 JSON 批注文件--}{++只需要管理一个 Markdown 文件++}。

{~~批注存储在外部文件中~>批注直接写入 Markdown 原文中~~}。
```

修改后：

```markdown
MarkReview 是一个轻量级 Markdown 审阅插件。

{==它第一版聚焦小而可用的 Markdown 批注和 AI 协作修改==}{>>第一版不要夸大范围，强调小而可用。<<}

用户只需要管理一个 Markdown 文件。

批注直接写入 Markdown 原文中。
```

## 修改检查清单

交付 AI 修改后，应确认：

- AI 没有新增 `{++`、`{--`、`{~~` 这类修订标记来表达自己的修改。
- 新增、删除和替换已经直接体现在正文里，可以通过 Git diff 查看。
- 原有 `{==内容==}{>>意见<<}` 批注仍然保留，批注意见没有丢失。
- Markdown 标题、列表、表格、代码块和链接没有被意外破坏。
- 批注意见已经反映到正文中，而不是仅仅移动或删除批注。

## 与插件功能的关系

`MarkReview: Export AI Prompt` 应优先生成与本文件一致的提示词模板。插件不需要在第一版理解复杂自然语言批注意见；复杂改写由 Codex 或其他 AI 完成。`MarkReview: Clean / Accept Changes` 是本地机械清理功能，不等同于 AI 按批注改写。
