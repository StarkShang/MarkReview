# MarkReview AI Workflow

## 使用场景

用户在 VS Code 中通过 MarkReview 给 Markdown 原文插入 CriticMarkup 标记后，可以直接把这份 Markdown 交给 Codex 或其他 AI。AI 根据标记完成修改，并输出不含 CriticMarkup 的干净 Markdown。

这个流程的核心是：Markdown 文件本身就是正文、批注和修订建议的唯一交接物。

## 用户操作流程

1. 在 VS Code 中打开 Markdown 文件。
2. 使用 MarkReview 命令添加批注、替换建议、删除建议或新增建议。
3. 检查文档中的 CriticMarkup 标记是否表达清楚。
4. 使用 `MarkReview: Export AI Prompt` 生成提示词，或复制下方稳定模板。
5. 将提示词和带 CriticMarkup 的 Markdown 一起交给 Codex。
6. 要求 Codex 输出干净 Markdown。
7. 将 AI 输出结果作为新的正文版本继续编辑。

## 稳定提示词模板

````text
你是一个严谨的 Markdown 编辑助手。请根据我提供的 Markdown 文档中的 CriticMarkup 标记修改正文，并输出干净 Markdown。

CriticMarkup 规则：
- {++新增内容++} 表示新增内容。请在最终正文中保留新增内容，并移除标记。
- {--删除内容--} 表示删除内容。请在最终正文中删除这部分内容，并移除标记。
- {~~旧内容~>新内容~~} 表示替换建议。请在最终正文中使用新内容替换旧内容，并移除标记。
- {==被标记内容==}{>>批注意见<<} 表示批注。请根据批注意见改写被标记内容，并移除高亮和批注标记。

处理要求：
- 只输出最终干净 Markdown，不要输出解释、分析过程或修改清单。
- 不要保留任何 CriticMarkup 标记。
- 保留原文的 Markdown 结构，包括标题层级、列表、表格、引用、代码块、链接和图片。
- 不要改写与批注无关的内容，除非为了保持上下文连贯必须做轻微调整。
- 如果批注意见不明确，请选择最保守、最符合上下文的改写方式。
- 如果 CriticMarkup 出现在代码块中，除非批注明确要求修改代码，否则保持代码块内容稳定。

下面是需要处理的 Markdown 文档：

```markdown
{{在这里粘贴带 CriticMarkup 的 Markdown}}
```
````

## Agent 处理规则

| CriticMarkup | Agent 应做的事 | 最终输出 |
| --- | --- | --- |
| `{++新增内容++}` | 接受新增内容 | `新增内容` |
| `{--删除内容--}` | 删除该内容 | 空 |
| `{~~旧内容~>新内容~~}` | 使用 `~>` 右侧内容替换旧内容 | `新内容` |
| `{==内容==}{>>意见<<}` | 根据意见改写被标记内容 | 改写后的正文 |
| `{==内容==}` | 如果没有批注意见，保守地保留内容并移除标记 | `内容` |
| `{>>意见<<}` | 如果缺少明确作用对象，根据上下文处理；无法判断时移除批注但不擅自大改正文 | 视上下文而定 |

## 示例

输入：

```markdown
MarkReview 是一个{++轻量级++} Markdown 审阅插件。

{==它可以做很多文档管理功能==}{>>第一版不要夸大范围，强调小而可用。<<}

用户{--需要维护额外的 JSON 批注文件--}{++只需要管理一个 Markdown 文件++}。

{~~批注存储在外部文件中~>批注直接写入 Markdown 原文中~~}。
```

期望输出：

```markdown
MarkReview 是一个轻量级 Markdown 审阅插件。

它第一版聚焦小而可用的 Markdown 批注和 AI 协作修改。

用户只需要管理一个 Markdown 文件。

批注直接写入 Markdown 原文中。
```

## 输出检查清单

交付 AI 输出前，应确认：

- 最终内容不包含 `{++`、`{--`、`{~~`、`{==`、`{>>` 等 CriticMarkup 起始标记。
- Markdown 标题、列表、表格、代码块和链接没有被意外破坏。
- 替换建议使用的是新内容，不是旧内容。
- 删除建议对应内容已经移除。
- 批注意见已经反映到正文中，而不是仅仅删除批注。

## 与插件功能的关系

`MarkReview: Export AI Prompt` 应优先生成与本文件一致的提示词模板。插件不需要在第一版理解复杂自然语言批注意见；复杂改写由 Codex 或其他 AI 完成。
